# mm-review 数模五门禁质检与独立评审

本技能把数学建模全流程切成五个不可跳过的门禁，规定每个门禁的进入条件、验收条款、失败依据、固定回执与返工闭环。作者自检、确定性脚本、独立验收三者互相不可替代：脚本负责机械项，Subagent 负责独立复现与语义审查，作者负责修正。

## 何时用 / 何时不用

用：

- 某阶段产物完成作者自检，需要独立判定能否解封下一阶段（M1→编程手，P1→全量计算，P2→论文手，W1→长篇正文，W2→交付）。
- 收到 FAIL 回执后要复验，或怀疑门禁通过后产物发生了未复验的实质变化。
- 交付前做一次评审视角扫描：significance、validity、reproducibility、claims-vs-evidence、统计误用、过度声明、模型与题意贴合度。
- 用户直接说「质检 / 自检 / 评审 / 门禁 / 验收 / 复核」。

不用：

- 还没有产物（仍在读题、选模型）：走 `mm-modeling`，不要空跑门禁。
- 只需要机械检查：直接跑 `tools/docx/scripts/self_check.py`、`tools/latex/scripts/latex_paper.py validate`、`roles/编程手/scripts/figure_audit.py`，不必再起 Subagent。
- 需要动手改产物、改代码或写正文：本技能全程只读，修改回 `mm-modeling` / `mm-coding` / `mm-paper`。
- 授权、材料、当届官方规则任何一项未到位：先补输入，否则派发出去只能得到 `BLOCKED`。

## 核心原则

1. **只读**：质检者读文件、跑只读命令、算哈希，绝不修改、移动、重命名受审产物或权威代码；发现的问题写成 finding 交回根因角色。
2. **独立**：质检者未参与该产物的编写与修正。作者自检、脚本退出码、独立验收是三条独立证据，任何一条通过都不能替代另一条。
3. **到点即验**：在门禁节点立即派发，禁止等全流程结束才首次验收；未通过不得进入后续高成本工作。
4. **证据锚定**：每条 finding 必须带 `文件:行号`、已执行命令加退出码加关键输出、页码或关键数值。没有锚点的意见不得写入回执。
5. **三值状态**：只有 `PASS` / `FAIL` / `BLOCKED`，没有「基本通过」；`FAIL` 不得被主 Agent 改写成通过。
6. **变化即失效**：受审输入的 SHA-256 或实质内容变化，相关 `PASS` 立即作废，必须复验。
7. **非补偿**：一个 P0 或 decision-bearing 失败不能被其他维度的高分、其他门禁的通过或排版质量抵消。
8. **不预置结论**：派发包只给材料、条款与命令日志，不给期望结论，不传范围外历史对话，避免结论污染。
9. **只报可证的**：缺材料写 `BLOCKED` 并列出缺什么，不用推测填满报告；未评估写 `NOT_ASSESSED`，不编造证据、页码或引用。

## 五门禁定义

| 门禁 | 阶段 | 通过后解封 | 不复验即失效的条件 |
|---|---|---|---|
| M1 建模终检 | 建模手交付前 | 编程手开工 | `题目分析报告.md`、`术语表格.md` 任一实质变更 |
| P1 最小可运行结果 | 纵向切片首次跑通后 | 全量计算、参数扫描、正式出图 | 数据、预处理、模型参数或求解入口变更 |
| P2 编程终检 | 代码、结果表、三类图、复现清单冻结后 | 论文阶段 | 代码、结果、图、复现清单任一变更 |
| W1 证据大纲 | 主张—证据映射与大纲完成后 | 长篇正文与排版 | 主张、证据路径、图表编号变更 |
| W2 论文终检 | 全部格式冻结且各确定性门禁返回 0 后 | 导出、打包、交付 | 正文、数据、图、规则来源任一变更 |

### M1 建模终检

- 进入前必须已完成：读完题目与全部附件并记录哈希或版本；模型合同八项（任务定义、数据、结论类型、模型、数学定义、实现、验证、风险）写入 `题目分析报告.md`；假设分级（关键 ≤3 条、可放宽合计 ≤7 条）并写明依据；`术语表格.md` 符号已按数学格式排版；作者自检逐条勾选；输入快照冻结。
- 验收条款：M1-a 子问题全覆盖且规范为 `q1..qN`；M1-b 每条假设有题目、文献或官方依据；M1-c 变量、参数、单位、目标函数、约束齐全且一符一义，无 `x_ij`、`alpha`、可见下划线；M1-d 每题独立模型体系 ≤2，物理近似按模型族计数；M1-e 可由 Python/MATLAB 实现且依赖写到包名或工具箱；M1-f 验证指标、真实数据、失败条件与回退路径明确；M1-g 文献可追溯到 DOI 或原始出版页；M1-h 只交付两个固定文件且写入 `PROJECT_ROOT`，未覆盖 `SKILL_ROOT`。
- 失败判定：条款不满足且影响结论（覆盖缺口、假设无依据、符号不可渲染、模型超量、依赖不可得、验证缺失、引用不可追溯、交付物污染）→ P0 `FAIL`；附件缺失、文献原文不可得、无哈希快照 → `BLOCKED`。

### P1 最小可运行结果

- 进入前必须已完成：数据读取、预处理、核心求解链首次跑通；一条最小命令可从 `PROJECT_ROOT` 直接执行；输入文件 SHA-256 已记录；M1 模型合同条款已被引用。
- 验收条款：P1-a 独立执行最小命令且退出码为 0；P1-b 每个驱动后续全量计算的模型族至少覆盖一个真实输入或结构等价小实例；P1-c 输入到结果可追溯（同一文件、同一参数、同一单位）；P1-d 单位、量级、范围、约束可行性与 M1 合同一致；P1-e 无 NaN/inf/溢出残留，随机性有显式种子。
- 失败判定：退出码非 0、单位或量级错误、约束不可行、与合同不一致 → P0；依赖缺失、数据不可读、无执行权限 → `BLOCKED`。P1 是纵向切片，不要求三类图、完整敏感性分析或最终性能。
### P2 编程终检

- 进入前必须已完成：代码、结果表、`raw_`/`process_`/`result_` 三类图（每类 ≥3 张、合计 ≥9 张、`q1..qN` 全覆盖）、建模流程图、`results/复现清单.json` 全部冻结；`check_figure.py --strict` 与带全部 `--questions` 的 `figure_audit.py --strict` 返回 0；作者自检完成。
- 验收条款：P2-a 重跑唯一复现命令并核对退出码与关键数值；P2-b 输入哈希、环境、种子、参数与复现清单一致；P2-c 边界、量纲、约束 sanity check 通过，统计量与区间由代码计算、无硬编码 p 值；P2-d 图表配额与语义（图型匹配变量、每个子问题有支撑图、SVG 与 ≥300 DPI PNG 成对）；P2-e 建模流程图节点连线与真实模型或代码一致、覆盖全部子问题、未替代结果图、未计入三类配额；P2-f 复现清单含可直接执行的命令、文件清单与依赖版本。
- 失败判定：重跑数值与论文引用不一致、图表配额或语义缺口、手写或伪造结果、流程图与代码不符 → P0；种子或参数缺失导致不可复现 → P1；无法重跑（缺依赖、缺数据、权限不足）→ `BLOCKED`。

### W1 证据大纲

- 进入前必须已完成：主张—证据映射（每个结论对应公式、结果表行列、图文件、代码输出或已核验 DOI）；章节落点与篇幅口径；符号说明表取自 `术语表格.md` 的「符号、含义、单位」三列；附录计划（必要性、主题、正文引用点、页数口径、是否要求完整代码）；两种格式共用同一正文与证据源。
- 验收条款：W1-a 每个必须回答的结论类型都有精确证据路径；W1-b 摘要拟用数值与实际结果一致；W1-c 公式、图表、引用都有章节落点，总体建模流程图已规划入文；W1-d 符号表三列且数学排版方式已定；W1-e 附录边界与完整代码要求已记录。
- 失败判定：核心证据缺口（结论无对应结果或图）→ P0，退回建模手或编程手补齐；证据路径无法定位到行、列或图编号 → `FAIL`；文献原文或附件未提供 → `BLOCKED`。W1 是内部检查，不新增交付物。

### W2 论文终检

- 进入前必须已完成：全部格式冻结；`self_check.py`、`tools/docx/scripts/office/validate.py`、`paper_format.validate_paper_structure`、LaTeX `validate --quality-checks` 均返回 0；实际渲染抽检完成；支撑材料已打包并解压验证。
- 验收条款：W2-a 当届规则（页面、摘要页、编号、页数、字体、提交格式）逐项对照当届官方文件；W2-b 每个结论有真实结果、图表、公式或文献支撑，摘要数值与正文、表、图、复现清单一致；W2-c 数值、有效位数与单位正确；W2-d 符号以可编辑 OMML 或 LaTeX 数学模式呈现，无可见下划线、反斜杠或公式源码；W2-e 附录单一主题、与正文双向引用，要求附完整代码时源码完整、可运行、与最终结果一致；W2-f 总体建模流程图已入文，图表编号连续、正文有引用、无孤儿图表；W2-g 无 `**`、反引号、标题 `#`、表格竖线、公式定界符、`[待补充]` 等残留；W2-h 实际打开 DOCX/PDF 抽检分页、公式、图表、页眉页脚、字体、参考文献；W2-i 双格式时 Word 与 LaTeX 数值和结论一致，`.conversion.json`、`.build.json` 哈希与实际文件一致；W2-j 支撑材料完整可解压，并已提醒用户自行上传确认。
- 失败判定：违反官方硬约束、数值不一致、Markdown 残留未清除、源码与结果不符、流程图失真 → P0；缺渲染证据、文件打不开、无法解压 → `BLOCKED`。未经用户或平台证据确认，不得声称已提交。

## 执行流程

1. **冻结快照**：对受审产物计算 SHA-256 与 mtime，写入 `inputSnapshot`。
   ```powershell
   Get-FileHash -Algorithm SHA256 "<ARTIFACT>" | Select-Object Hash, Path
   (Get-Item "<ARTIFACT>").LastWriteTime.ToString("o")
   ```
2. **定门禁与条款**：按当前阶段选门禁，把该门条款原样抄进派发包，避免质检者自行改判标准。
3. **选质检者**：未参与被审产物的编写与修正；单阶段任务只跑该阶段门禁，不为每个函数、每张图、每段文字重复派发；同一名始终未参与编写与修正的质检者可以连续执行中途门禁与终检。
4. **组装派发包**：题目与用户要求、只读附件路径、产物路径与哈希、条款清单、上一门禁回执、关键命令与日志。不写「主 Agent 认为已正确」，不传范围外对话。
5. **只读派发**：用下节模板，一次派发一个门禁；可选协作（规则核验、附件盘点、文献调研、算法原型）默认关闭，需用户明确启用。
6. **校验回执**：schema 是否齐全、`level` 是否合法、每条 finding 是否有锚点、`status` 与 findings 是否自洽（出现 P0 或 P1 仍写 `PASS` 时退回重做）。
7. **判定与路由**：`PASS` 解封；`FAIL` 出返工单并按根因路由（实现问题回编程手，公式、约束、参数合同问题回建模手，表述与格式回论文手）；`BLOCKED` 补齐缺失项后重新派发，不得降级为受限通过。
8. **复验记账**：复验只覆盖修正项与受影响条款，并做漂移检查；回执与哈希清单存入 `PROJECT_ROOT/质检/`，供 W2 与交付核对。

9. **并行边界**：只读质检可以并行派发（如 M1 与附件盘点同时进行、多个子问题的独立复现），但同一产物在同一时刻只能有一名修改者；不并行修改 `题目分析报告.md`、权威代码、结果表或论文正文，不按章节多人并写论文，不分别生成互不共享正文的 Word 与 LaTeX。

## 回执与返工

固定 schema：`{scope, inputSnapshot, status, evidence[], findings[{level,text}], rework}`。缺字段的回执按无效处理，不计入验收。

| 字段 | 合格填写 | 不合格填写 |
|---|---|---|
| `scope` | `{"gate":"P1","clauses":["P1-a"…"P1-e"],"uncovered":["未覆盖 q4 数据分支"]}` | `{"gate":"全部"}`、只写「本次检查了代码」、漏 `uncovered` |
| `inputSnapshot` | 每个受审文件的绝对路径加 SHA-256 加 mtime，或明确版本号 | 只写文件名、写「最新版」、无哈希、把 `SKILL_ROOT` 文件当产物 |
| `status` | `PASS`／`FAIL`／`BLOCKED` 三值之一，且与 findings 自洽 | `PASS` 却列 P0；`FAIL` 却说基本可用；自造 `PASS_WITH_NOTES` |
| `evidence[]` | `figure_audit.py --questions q1 q2 q3 --strict -> exit 0`；`论文.docx 第 7 页表 3 数值 0.873 与 results/结果.csv:12 一致` | 「已检查，无问题」、无命令无行号的复述、把作者自检结论当证据 |
| `findings[]` | `{"level":"P0","text":"缺 q3 正式图（figures/ 无 result_q3_*，见目录清单）"}` | `{"level":"高","text":"图表质量待提升"}`；一条 finding 混装三个问题 |
| `rework` | `{"role":"建模手","mustFix":["补 q3 约束的可行性验证（题目分析报告.md:64-70）"],"reverifyFrom":"M1-c、M1-f"}` | `{"role":"作者自己看看"}`、只写「请修改」、不给复验入口 |

`level` 取值固定：`P0` 正确性或官方硬约束；`P1` 复现性、一致性或关键质量；`P2` 非阻塞改进。存在未解决的 P0 或 P1 只能 `FAIL`；缺依赖、权限、输入或可验证证据只能 `BLOCKED`。

### BLOCKED 的正确用法

- 触发条件四类：缺依赖或权限、缺输入附件、缺可验证证据、官方规则未核验。命中任一类用 `BLOCKED`，不用 `FAIL` 掩盖缺口，也不用 `PASS` 兜底。
- 回执必须写清「缺什么、影响哪一条款、补齐后从哪一步重入」，例如：缺 `figures/result_q3_*.png`，影响 P2-d 与 W2-b，补齐后从 P2-d 重入。
- 主 Agent 补齐后原样重发同一门禁；不得把 `BLOCKED` 当作受限通过，也不得在同一缺失条件下反复重试同一命令。

### 返工单模板

```text
返工单 {GATE}-{序号}
根因角色：{建模手 | 编程手 | 论文手}
失败条款：{M1-c、M1-f}
必须修正：1) …（证据：题目分析报告.md:88 缺单位）2) …（证据：命令输出 exit 1 第 12 行）
禁止做法：改条款、删检查项、把 P0 降级为 P2、绕过复验直接宣称通过
复验入口：{GATE}-{受影响条款}；复验者沿用原质检者或另一名未参与者
冻结要求：修正后重算 SHA-256 并写入新的 inputSnapshot
```

### 复验范围与漂移判定

- 复验范围三条规则：第一，全部 P0 必须逐条复验；第二，只复验受影响条款，条款文本不改可复用原检查表；第三，修正引入新章节、新图或新参数时，扩到相邻条款与依赖门禁（如 P2 改动波及 W2 的数值与图引用）。
- 漂移判定：哈希变则该门 `PASS` 立即失效并按 `FAIL` 处理；只有 mtime 变而哈希不变则记录并在复执时抽样复核；无快照可查视为未通过，先重建快照再验。
- 同一门禁原则上不超过 2 轮复验；仍未通过则缩小交付范围并按受限交付处理，回执写明未覆盖项与原因，保护当前可提交版本。

### 评审视角自评表（0–5）

分数只作门禁自评尺，不做跨稿排名、不换算成通过概率；任一维度低分带决定权时，其他维度高分不能抵消。

| 维度 | 判据（0 缺失或错误，1 明显不足，2 部分成立，3 达标，4 扎实，5 可核验的出版级水平） | 是否有决定权 |
|---|---|---|
| significance 重要性 | 结论是否回答题目真正关心的量，而非容易算的替代指标 | 是 |
| validity 有效性 | 模型假设、数据与推断链能否支持所下结论 | 是 |
| reproducibility 可复现 | 唯一命令重跑得到同一关键数值，种子、参数、输入哈希齐备 | 是 |
| claims-vs-evidence 主张—证据 | 每个结论都能定位到公式、结果表、图、代码输出或已核验文献 | 是 |
| 统计误用 | 区间与效应量、多重比较校正、等价性判定、样本量理由、不确定性表达 | 是 |
| 过度声明 | 结论是否超出数据范围（外推、因果化、普适性、政策建议） | 是 |
| 模型与题意贴合度 | 模型是否回答本题所问，而非套用一个相近的常见模型 | 是 |

| 判定 | 阈值 | 动作 |
|---|---|---|
| 拒（整门不通过） | 任一有决定权维度 ≤1，或核心证据缺失 | `FAIL` 加返工单，退回根因角色重做，相关门禁不得跳过 |
| 大修 | 任一维度 ≤2，或仍有未解决 P0 | `FAIL`，退回原阶段，修正后整门复验 |
| 小修 | 全部维度 ≥3 且仅剩 P2 | `FAIL` 列清单，修 P2 后按受影响条款复验 |
| 通过 | 全部维度 ≥3 且无 P0、P1、P2 | `PASS`，解封下一阶段 |

## 与数模三角色的衔接

| 角色 | 作者自检来源 | 承担门禁 | 未通过时 |
|---|---|---|---|
| 建模手 `mm-modeling` | `roles/建模手/references/质检清单.md` | M1 | 禁止编程开工，修正后整门复验 |
| 编程手 `mm-coding` | `roles/编程手/references/质检清单.md` | P1、P2 | P1 未过不得全量计算与正式出图；P2 未过不得写论文 |
| 论文手 `mm-paper` | `roles/论文手/references/自审框架.md` | W1、W2 | W1 未过不得写长篇正文；W2 未过不得交付 |

- 三角色共用同一份回执与漂移记录；返工按根因路由，不按产物目录路由：实现问题回编程手，公式、约束、参数合同问题回建模手，表述、格式、排版问题回论文手。
- 评审视角分工：建模手负责 significance 与模型贴合度，编程手负责 validity 与 reproducibility，论文手负责 claims-vs-evidence 与过度声明；独立质检者仍需覆盖全部七维度，分工只是加权，不是范围豁免。
- 截止时间紧张时按 `references/交付与截止时间协议.md` 保护可提交版本：优先修复阻断提交的 P0，非必要优化在 V1 副本上做，不因追求局部完美回到无版本可交的状态。
- 运行环境没有 Subagent 能力时，继续跑确定性脚本，回执状态只能是 `BLOCKED` 或受限交付，不得声称全部门禁通过。

## 常见失败模式

1. **只发「帮我审一下」**：不带门禁、条款、产物路径与哈希，回执必然空泛。改用派发模板，逐条抄入门禁条款。
2. **作者自检冒充满意验收**：自己点自己通过，P0 在进入下一阶段后放大。要求未参与者、只读、独立重跑。
3. **脚本 exit 0 代替语义审查**：`figure_audit.py` 全过，但图答的不是子问题所问。脚本只作机械证据，语义另查。
4. **BLOCKED 被误用**：缺数据写成 `FAIL` 掩盖缺口，或反复重试同一命令。先列缺失项再派发，补齐后重跑同一门禁。
5. **门禁后偷偷改产物**：画图前微调结果表、改一句摘要数值却不复验。哈希一变即 `FAIL`，按漂移规则重走受影响门禁。
6. **finding 无锚点**：「方法不够严谨」「图表质量待提升」无法返工。每条必须定位到行、页码或命令输出。
7. **让质检者顺手改文件**：独立性与产物版本同时失效。只读不是建议，是派发的前置条件。
8. **为凑视角编造分歧**：虚构审稿分歧或压掉真实重叠。真实重叠是佐证，保留并标注来源，不制造平衡。
9. **W2 只看源文件不看渲染**：公式变成截图、分页崩坏、图表错位在源码里看不出来。必须打开实际 DOCX/PDF 抽检。
10. **PASS 未复算哈希就交付**：V1 被原地覆盖，出错无法回退。交付前重算哈希并与快照比对。
