# mm-paper — 数模竞赛论文的写作与结构

输入是建模与求解的产物，输出是一篇每句话都能被人翻开证据核对的论文。本技能只管「怎么把已有证据写成论文、怎么判定写成了」，不重新建模、不改数值。

## 何时用 / 何时不用

**用**：

- 手上有 `题目分析报告.md`、`术语表格.md`、代码、结果表与 `figures/`（或缺失项已登记），要产出摘要页、正文各节、Summary Sheet 或终稿。
- 已有稿子，要判断章节是否齐全、每个结论是否有证据落点、摘要与正文是否自相矛盾。
- 中文稿内容已定，要做英文重写（美赛），或只做语言层润色而结构不动。

**不用**：

- 模型未定或结果未跑：回建模手/编程手补齐证据，W1 证据大纲未返回 `PASS` 不开始正文。
- 只要格式转换与排版（Markdown→DOCX、LaTeX 编译、公式转 OMML）：走 `tools/docx`、`tools/latex`，本技能只给结构与题注口径。
- 只要找文献与核验 DOI：走 `tools/paper_search`，核验完成后把元数据交回参考文献节。

**进入判定**：关键输入缺 2 项以上，先补输入再动笔；只缺 1 项时可按占位继续写，但在映射表标 `待补`，交付前清零。

## 核心原则

1. **摘要与结果是评分入口**。评阅人先用几十秒筛摘要与关键图表，再决定是否细读；摘要加结果表述合计权重约 50%，正文写得再工整也补不回这一段的失分。
2. **结构服从当届官方模板**。官方有模板就照它的章节顺序、页数、字体、编号页；官方没规定时才用本技能默认章节序，且不得把默认值写成"官方要求"。
3. **每个结论都可追证据**：公式编号、结果表行列、图编号、代码输出或已核验文献，命中其一，且第二个人能按定位打开核对。
4. **数值即论证**。报数必带单位、统计口径与对照基准；"效果良好""显著提升"不构成结果。
5. **一个子问题最多两个独立模型体系**；同一机理的不同精度展开按一个模型族叙述，不靠拆模型虚增创新。
6. **不虚构**：数据、实验、文献、官方规则一律不编；缺失写占位并登记，交付前逐项清零。
7. **创新必须带对比验证**（改进前后、不同方法、灵敏度），没有对比的"创新"降级为方法描述。
8. **动词强度跟证据强度走**：有直接数值证据用 show/demonstrate，只有趋势用 suggest/indicate，纯推导用 may/could。

## 执行流程

### 1. 锁定规则与语言

- 动作：确认竞赛、届次、语言、篇幅上限、摘要页要求、字体与提交格式；打开当届官方模板与格式说明并记录来源。
- 产出物：规则清单（届次、正文页上限、摘要页、字体字号、文件命名）。
- 判定：每条规则都能指到官方文件或用户明示；往届经验不得以规定口吻写入。

### 2. 定章节顺序与字数配比（国赛体基线）

- 动作：按下列顺序排目录，给每节分配目标占比；官方模板有差异时以官方为准并在此处注明偏离原因。
- 产出物：带配比的章节大纲（一页以内）。
- 判定：十二节齐全（缺附录须写明官方不允许），占比合计 100%。

| 序 | 章节 | 写作硬约束 | 配比 |
|---|---|---|---|
| 1 | 摘要页 | 独立一页，四段式；不出现公式、图表、文献引用；关键词 3–5 个（≥2 方法词 + ≥2 领域词） | 单独成页 |
| 2 | 问题重述 | 用自己的话，只写任务、输入、约束、输出；不抄题、不自造背景数据 | 5% |
| 3 | 问题分析 | 每子问题一段：难点 → 为什么此模型对付得了 → 与相邻问的衔接 | 8% |
| 4 | 模型假设 | 4–8 条，每条标依据类型（文献/数据/几何/尺度）；假设不得替代可调参数 | 4% |
| 5 | 符号说明 | 只有「符号、含义、单位」三列，与 `术语表格.md` 同源，全文只定义一次 | 3% |
| 6 | 模型建立 | 变量与参数 → 假设依据 → 数学定义（目标/约束/边界）→ 逐式编号 | 22% |
| 7 | 模型求解 | 算法、参数取值、收敛与停止准则、复杂度；附唯一复现命令 | 18% |
| 8 | 结果分析与检验 | 每条结论 1 图 + 1 数 + 1 句解释；必须与基线或实测对比 | 15% |
| 9 | 灵敏度/误差分析 | 参数扫描必须重新求解（不是代回解析式），给弹性、阈值与失效点 | 10% |
| 10 | 模型评价与推广 | 优点 3 条各绑证据，局限 3 条各绑假设/数据/算法，推广写清成立条件 | 6% |
| 11 | 参考文献 | 8–15 条，正文与文末双向对应，出版信息与 DOI 已核验 | 4% |
| 12 | 附录 | 只放长推导、补充参数表、伪代码、官方要求的完整代码；与正文双向引用，编号 A.1 | 不计正文 |

正文各节合计 100%（不含摘要页与附录）。页数上限以当届官方为准，且以渲染成 PDF 后的实际页数为准，不按字符数估算。

### 3. 建 Claim-Evidence 映射（W1）

- 动作：为每个子问题列出拟写主张，逐条挂证据定位；标出缺口后面向建模手/编程手补齐。
- 产出物：主张—证据映射表（只作内部验收，不进论文）。
- 判定：每子问题 ≥3 条主张（建模、求解、验证各 ≥1），状态列无 `待补`/`待核` 才允许写正文。

|---|---|---|---|---|---|
| C1 | 最优配比为 (0.42, 0.31, 0.27) | 结果表 | `results/q1_opt.csv` 第 3 行；表 2 | 6.2 | 已验证 |
| C2 | 改进 GA 较基线缩短配送距离 18.3% | 代码输出 | `run_q1.log` L42；图 3 | 7.1 | 已验证 |
| C3 | μ 超过 0.6 后解失效 | 灵敏度图 | 图 7(b) | 9.2 | 待补重跑 |
| C4 | 算法复杂度为 O(n log n) | 公式 | 式(11) | 6.3 | 已验证 |
| C5 | 与文献[7]误差同量级 | 文献 | 已核验 DOI 记录 | 8.4 | 待核 |

### 4. 分节写正文

- 动作：按「模型建立 → 求解 → 结果 → 灵敏度 → 评价 → 重述/分析 → 摘要」的顺序写；每段一个论点，先给事实或推理，再解释含义；图表先在正文被引用，再出现。
- 产出物：单一正文源（Markdown 或 LaTeX 主稿），Word 与 LaTeX 都从它派生，不并行改写。
- 判定：各节占比落在大纲 ±3 个百分点；无孤儿图表（每图每表正文至少引用一次）；无 `[待补充]`。

### 5. 语言与符号校准

- 动作：逐句过语态、时态、符号、量纲四道关，再按对照表替换空泛与机翻表述。
- 产出物：语言修订记录（改了哪句、为什么）。
- 判定：禁词表零命中；同一符号全文一个含义；数值与单位成对出现。

规范要点：

- 语态：方法与求解用被动或"式(3)给出"；结论句用主动且主语具体（"模型三在 μ≥0.6 时发散"），不写"我们认为"。
- 时态（英文）：Methods 过去时；Results 用过去时陈述数值、现在时解释含义；Discussion 现在时。同段不混用。
- 符号：变量斜体、向量矩阵粗体、单位正体；首次出现即定义并进符号表，禁止一符二义。
- 公式：独立成行、右侧编号、正文写"式(3)"；不跳步，跳步处给引用或推入附录。
- 量纲与有效数字：数值必带单位；有效数字不超过输入精度（一般 3–4 位）；百分比与百分点分开写；误差写 `±` 并给置信水平或区间。
- 禁词：我们认为、显然、众所周知、毋庸置疑、效果良好、大幅提升、具有一定的意义。
- 机翻腔：删"进行了一个…的操作""基于此我们可以得出结论""在…的方面"，改动词直述。

### 6. 美赛（MCM/ICM）英文化

- 动作：先按英文化三阶段（提取论证 → 写英文草稿 → 三轮校准）重写，再套官方版式；不逐字翻译句子。
- 产出物：英文正文 + 独立 Summary Sheet + 术语英译表（全文统一用词）。
- 判定：无中文标点与全角字符；术语表命中率 100%；Summary Sheet 数值与正文逐一对齐。

版式与表达要点：

- Summary Sheet：正文前独立一页，一页装完，无公式、图表、文献；构成 = 题目重述一句 + 每问方法一句 + 关键数值 + 结论与适用条件 + 关键词。
- 页眉页码：每页含 Team Control Number 与页码，位置照官方模板；页眉缺失按官方要求直接算违规。
- 字体版式：正文 12pt（Times New Roman 或 Computer Modern），图注表注 9–10pt，行距页边距照模板；图内字号不小于 8pt，缩放后仍可读。
- 表达差异：中文并列短句改英文主从结构；删"本文"式开头（"This paper establishes…" → "We develop…" 或被动）；百分号写 `%`；数字与单位间留空格（12.3 kg）。
- 一词一概念：同一概念全文一个英文词，缩写首次出现给全称，正文与摘要各自独立定义。

| 中文 | 英文（论文中用词） | 中文 | 英文（论文中用词） |
|---|---|---|---|
| 建模 | model development | 模型假设 | model assumptions |
| 符号说明 | notation / list of symbols | 决策变量 | decision variable |
| 目标函数 | objective function | 约束条件 | constraints |
| 可行域 | feasible region | 模型求解 | solving the model |
| 算法 | algorithm | 迭代与收敛 | iteration and convergence |
| 数值实验 | numerical experiments | 算例 | test instance |
| 基线 | baseline | 结果分析 | analysis of results |
| 模型检验 | model validation | 灵敏度分析 | sensitivity analysis |
| 误差分析 | error analysis | 稳健性 | robustness |
| 模型评价 | model evaluation | 模型推广 | model extension |
| 最优解 | optimal solution | 启发式算法 | heuristic algorithm |
| 运行时 | runtime | 计算复杂度 | computational complexity |

- 动作：跑结构与格式门禁，再从实际文件抽检，不信"看起来对"。
- 产出物：检查记录（含实测页数、失败项定位到页码/章节/命令）。
- 判定：门禁全部返回 0；抽取 5 处关键数值与代码输出逐字一致；DOCX 提取文本无 `**`、反引号、`$`、`[待补充]`。

- 动作：首次满足硬约束时存 Checkpoint V1，后续改动在副本上做；内容冻结后统一导出。
- 产出物：`完整论文.docx`（用户要求时加 LaTeX 工程与编译 PDF）。
- 判定：最终包能打开、页数合规、无残留占位符；登录上传与提交确认由用户完成，未经凭证不声称已提交。

## 摘要写作模板

摘要单独成节，因为它决定评阅人是否往下读。三条硬规则：最后写、只从终稿正文反向摘录、每个子问题必须出现具体数字。

句子骨架（四段，一段一句或两句）：

1. 背景一句：对象 + 冲突或约束（不做文献综述，不写"随着…的发展"）。
2. 方法每子问题一句：模型名 + 关键机制 + 求解手段（写清"用什么对付什么"，不是术语堆叠）。
3. 关键结果：每问至少一个数字，带单位与对照基准（与基线、实测或理论上界比）。
4. 结论一句：适用条件 + 决策含义或推广边界。
5. 关键词：≥2 个具体方法词 + ≥2 个题目领域词，不用"数学建模""优化"凑数。

300–500 字示范骨架（`⟦⟧` 内为必须替换的数值或名称，交付前逐槽清空）：

```text
针对⟦题目对象⟧在⟦约束条件⟧下的⟦核心任务⟧问题，本文建立以⟦目标量⟧为目标、以⟦约束一⟧与⟦约束二⟧为约束的⟦模型族名称⟧。针对问题一，以⟦决策变量⟧为决策变量建立⟦规划类型⟧模型，用⟦求解算法⟧求得最优⟦指标⟧为⟦数值+单位⟧，较⟦基线方案⟧改进⟦x.x%⟧。针对问题二，引入⟦耦合机制或权重项⟧构建⟦模型名⟧，经⟦迭代次数⟧次收敛，得到⟦关键量⟧=⟦数值⟧，与实测值的相对误差为⟦x.x%⟧。针对问题三，将⟦不确定性或多目标权衡⟧纳入模型，得到⟦方案或前沿⟧：当⟦参数⟧在⟦区间⟧内变化时⟦指标⟧波动不超过⟦x.x%⟧，失效阈值为⟦数值⟧。对⟦关键参数⟧做灵敏度分析，弹性系数为⟦数值⟧，说明⟦一句因果结论⟧。结果经⟦交叉验证/残差检验/文献对比⟧检验，⟦误差指标⟧为⟦数值⟧。模型适用于⟦成立条件⟧，可推广至⟦适用场景⟧。
```

自检：把每个 `⟦⟧` 换成真实数值后，摘要里不剩一个形容词型结论；若某问填不出数字，回第 3 步补证据，而不是把它改写成"效果较好"。

英文 Summary Sheet 用同一骨架的英文式：`To address ⟦problem⟧ under ⟦constraints⟧, we develop ⟦model⟧. For Problem 1, ⟦method⟧ yields ⟦value⟧, ⟦x.x%⟧ better than ⟦baseline⟧. … The model applies when ⟦condition⟧ and extends to ⟦scenario⟧.`

## 检查清单

**结构与格式**

- [ ] 十二节齐全或已说明官方偏离；摘要页独立、无公式图表引用。
- [ ] 每节占比在配比 ±3 个百分点内；页数为渲染实测值且不超当届上限。
- [ ] 图表连续编号、有题注、正文至少引用一次；表格可编辑，三线表无竖线。
- [ ] 符号说明只有三列且与 `术语表格.md` 一致；公式为原生 OMML 或可编译源码，无截图。

**证据与数值**

- [ ] 映射表每条主张状态为"已验证"，摘要在内。
- [ ] 摘要、正文、表格、图、代码输出五处的同一数值逐位一致。
- [ ] 灵敏度分析每个扫描点都重新求解并记录收敛状态。
- [ ] 参考文献与正文双向对应，DOI 与出版信息已核验，无自造条目。

**语言**

- [ ] 禁词零命中；机翻腔句式已改写。
- [ ] 英文稿无中文标点、全角字符；术语一词一译，缩写首现给全称。
- [ ] 结论句的动词强度与证据强度匹配，无"证明"式过度断言。

**交付**

- [ ] Checkpoint V1 已另存，终稿在副本上产出。
- [ ] DOCX 提取文本无 Markdown 残留与 `[待补充]`；LaTeX 无未解析引用与文献。
- [ ] 上传与提交由用户确认，成功凭证已留存。

## 常见失败模式

- **摘要通篇"效果良好"**｜症状：无一个具体数值，全是评价词。原因：等结果定稿才起草摘要，又没回填数值。处理：按摘要骨架留 5 个数值槽，交付前逐槽替换，填不出就回第 3 步补证据。
- **摘要与正文打架**｜症状：摘要写 LSTM、正文实现是 BP；摘要百分比与表 2 不同。原因：摘要先写或正文改稿后未回同步。处理：摘要只从终稿反向摘录，正文一改就在同一次编辑里回改摘要，纳入 W2 必检。
- **图表断号或孤儿图**｜症状：图 5 后面直接图 7，有图正文没人提。原因：编程手批量改名后编号按文件名排序，正文引用漏写。处理：以最终图文件清单为源一次性重排编号与题注，用结构校验脚本卡住孤儿图表。
- **灵敏度只改代入值**｜症状：参数表变了，最优解没变。原因：把参数代回解析式当成"重新求解"。处理：每个扫描点重跑求解器并记录命令与收敛状态，图上标出失效阈值。
- **一符多义**｜症状：同一符号在 6.1 是成本、9.1 是系数。原因：多人分节写、符号表未同步。处理：符号只从 `术语表格.md` 取，新符号先入表再入文，定稿前做一次符号一致性抽查。
- **假设堆成免责清单**｜症状：12 条假设，每条都以"假设…为常数"兜住漏洞。原因：用假设替代建模工作。处理：压到 4–8 条，每条标依据类型；无依据的假设改成模型参数或删掉，让局限出现在评价节。
- **机翻腔与模板句**｜症状："进行了一个优化的操作""基于此我们可以得出结论"。原因：中→英→中往返或套用通用模板。处理：按第 5 步对照表改动词直述，删掉"进行/基于此/在…方面"三类框架词。
- **附录吞掉核心论证**｜症状：正文只剩结论，推导和关键对照全在附录。原因：正文写不下就往外搬。处理：正文留模型、关键公式、结果与验证；附录只放长推导、补充参数表与官方要求的完整代码，编号 A.1 并在正文双向引用。
